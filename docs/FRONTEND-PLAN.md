> Один файл: всё, что нужно сделать на фронтенде, по этапам — как `CODING-PLAN.md` для бэкенда.
> Архитектура и правила слоёв — в [05-frontend-architecture.md](05-frontend-architecture.md).
> Отмечаем `[x]` по мере готовности. После каждого этапа: `typecheck` + `lint` + `build` → коммит → push `kholid` → merge в `main`.

## Стек и договорённости

| Что | Решение |
|---|---|
| Фреймворк | Next.js 16 (App Router, Turbopack), React 19, TypeScript strict |
| Стили | Tailwind 4, токены в `src/shared/ui/styles/globals.css` |
| Архитектура | FSD: `app → widgets → features → entities → shared` (импорт только вниз) |
| Данные | Серверные компоненты + `apiFetch` (ISR `revalidate`) для публичных страниц; TanStack Query — для корзины, кабинета, админки |
| Формы | React Hook Form + Zod (`@hookform/resolvers@5`), тексты ошибок как в API |
| Типы API | `npm run api:types` → `src/shared/api/schema.d.ts` (из Swagger бэкенда) |
| Иконки | lucide-react |
| Деньги | API отдаёт **дирамы** (целые), показываем через `formatMoney()` → «1 250 сом.» |
| Телефоны | `+992XXXXXXXXX`, показываем через `formatPhone()` |
| Язык | Русский интерфейс, `lang="ru"`; таджикский слоган в шапке/подвале |

### Дизайн

- Цвета логотипа: жёлтый `#FFB800` (brand) + чёрный `#0a0a0a` (ink), светлый фон, есть тёмная тема.
- Шрифты: Manrope (заголовки), Inter (текст), кириллица.
- Скругления карточек `--radius-card`, мягкие тени, жёлтые акценты, «строительная» диагональная штриховка в hero.
- Mobile-first: всё проверяем на 360 px, без горизонтального скролла.

### Авторизация (BFF)

- Токен Sanctum **никогда** не попадает в JS браузера: Route Handlers `src/app/api/auth/*` вызывают Laravel и кладут токен в httpOnly cookie `bakht_token` (Secure, SameSite=Lax, 24 часа).
- Все запросы, требующие входа, идут через `src/app/api/proxy/[...path]/route.ts`: берёт cookie → добавляет `Authorization: Bearer` → проксирует в `API_URL`.
- `src/proxy.ts` (бывший middleware) — редирект гостя с `/account/*`, `/checkout` на `/login?next=…`; с `/admin/*` — если нет cookie.
- Роль проверяется на сервере (`GET /me` в layout кабинета/админки): `client` → кабинет; `manager`/`admin` → админка; лишнее прячем, но сервер всё равно проверяет права.
- Гость **только смотрит**: кнопки «В корзину», «В избранное», «Оформить» у гостя ведут на вход с возвратом назад.

- [x] Тексты на ru/tg/en

**Как работает заказ (показываем клиенту):**

1. Клиент оформляет заказ → статус **«Новый»**.
2. Менеджер звонит в течение 15–30 минут (в рабочее время), уточняет объём, подъезд, разгрузку и цену доставки → **«Подтверждён»**.
3. Клиент оплачивает: наличными в офисе или переводом на карту. Менеджер проверяет поступление и отмечает **«Оплачен»**.
4. Склад собирает заказ → **«Собирается»**.
5. Водитель везёт → **«В пути»** (без оплаты сервер не даст поставить этот статус — `ORDER_NOT_PAID`).
6. Клиент принимает → **«Выполнен»**.

Все статусы меняет менеджер вручную в админке; клиент видит их в кабинете и получает уведомления.

**API:** `POST /orders`, `GET /me/addresses`, `GET /settings/public` (группы `delivery`, `payment`)
